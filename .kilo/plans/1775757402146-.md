#### B. Vercel-specific notes
Add a callout block under the Vercel button:

> **⚠️ Vercel + SQLite:** Vercel is a serverless platform — the filesystem is ephemeral and SQLite (`file:./dev.db`) will not persist between requests or deployments. For production Vercel deployments, replace `DATABASE_URL` with a hosted database compatible with Prisma:  
> - [Turso](https://turso.tech/) (hosted SQLite, minimal config change)  
> - [Neon](https://neon.tech/) (serverless Postgres)  
> - [PlanetScale](https://planetscale.com/) (serverless MySQL)

#### C. Railway-specific notes
Add a short note under the Railway button explaining that Railway supports persistent volumes, so SQLite works as-is, and that `DATABASE_URL` can be left as `file:./dev.db`.

### railway.toml — new file

```toml
[build]
builder = "NIXPACKS"

[deploy]
startCommand = "npx prisma generate && npx prisma db push && npm start"
healthcheckPath = "/"
healthcheckTimeout = 100
restartPolicyType = "ON_FAILURE"
restartPolicyMaxRetries = 3
```

This ensures Prisma client generation and schema push run automatically on every Railway deploy before the app starts.
